# AGENTS

## Overview

Sway Things is a GTK4 settings app for the sway Wayland compositor (and SwayFX), written in Rust: a core without GTK,
the `sway-things` CLI and the `sway-things-gui` app. What each release contains is in `CHANGELOG.md`; what is built and
what is planned, per page, is in `wiki/Feature-Catalog.md`.

This file is the entry point for agents. It states the hard rules and the traps, and links the canonical docs instead of
restating them. Keep it that way: a fact belongs in one place.

## Hard rules

Never break these, even if a task seems to ask for it. Ask instead. They are the
[engineering rules](CONTRIBUTING.md#engineering-rules-non-negotiable), numbered the same; the details are there.

1. **Never write a file Sway Things didn't create**, above all the user's `~/.config/sway/config`. The only exceptions
   are official programmatic stores (GSettings/dconf, D-Bus services).
2. **Never build shell strings.** `Command` with argument arrays; never `sh -c`.
3. **External strings are data.** Device names, SSIDs, Bluetooth names, file and window names go through the typed sway
   command builders, and into GTK only as plain text.
4. **No `unsafe`.**
5. **No panics outside tests:** no `unwrap`/`expect`/`panic!`/`todo!`/`dbg!`. Never weaken the workspace lints; a needed
   `#[allow]` states its `reason`.
6. **No privileged code, no daemon.**
7. **Generated sway config passes `sway --validate`** before it atomically replaces the old file. No network access, no
   telemetry.
8. **No tokio;** `crates/core` stays executor-agnostic.
9. **REUSE header** on every source file.
10. **Workflows:** actions pinned to a full SHA, downloaded tools and images pinned, least-privilege permissions.
11. **New settings start in the registry** (`crates/core/src/registry/`).
12. **Check commands live only in `scripts/`.**

## Traps

- **Never run sway on the host.** `just check` and `just lint` are safe: offline, no sway. Tests against a real sway and
  the GUI tests run only in containers (`scripts/check-integration.sh`, whose default runs every container;
  `just check-all`). `just checks` lists every check with where it may run.
- **Translatable strings:** mark UI strings with `msg!("…")` and show them with `tr`; after adding or changing one, run
  `scripts/update-pot.sh` and commit `po/sway-things.pot`, or `check-pot.sh` fails
  ([Translatable strings](CONTRIBUTING.md#translatable-strings)).
- **Regenerated files are committed:** after changing the CLI's commands, arguments or help texts, or the GUI's
  argument, run `scripts/update-cli-docs.sh` and commit `data/man/` and `data/completions/`. After changing what a
  setting generates, refresh the fixtures with `SWAY_THINGS_UPDATE_FIXTURES=1 cargo test -p sway-things-core` and review
  the diff in `ci/integration/`.
- **Docs in the same change:** update `wiki/` so it describes the new state, and tick or strike through the item in
  `wiki/Feature-Catalog.md`.
- **MSRV 1.85:** no language features or crates that need a newer rustc. `check-packaging.sh` checks that the MSRV and
  the version agree everywhere.
- Before finishing, run `just fmt` and `just check` (or the relevant `scripts/check-*.sh`).

## Conventions

The workflow is in [CONTRIBUTING.md](CONTRIBUTING.md); the parts agents get wrong most:

- Conventional Commits with the types from `.conventional-commit-types.json`, scope = page id or area. PRs land as merge
  commits, so every commit must be meaningful on its own. Rebase, never merge `main` in.
- Branches: `<type>/<issue>-<slug of the issue's full title>`. PR title = issue title, `Closes #N`; labels, issue type
  and Effort belong on the issue, not the PR.
- Don't hard-wrap PR descriptions, issue bodies or comments: GitHub renders every line break there.
- American English everywhere. Labels only through `.github/labels.yml`.
